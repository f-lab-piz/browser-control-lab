# PR #16 B01D 정확 head 독립 리뷰

## 발견 사항

**확정된 P0/P1/P2/P3 발견 사항 없음. 판정은 PASS다.** 지정 base→head 전체 변경과 연결 제품 코드·테스트·계약, B01D 4개 부모/6개 조건을 검토했다. PR본문·기존 구현 보고서·PASS는 검증할 주장으로 취급했다. 제품·테스트·문서 원본은 수정하지 않았고 scratch와 결과만 ignored `.local/`·`output/`에 기록했다. 원격 댓글·리뷰·승인·머지는 수행하지 않았다.

reset의 성공을 내부 `keys.clear`나 HTTP 200만으로 판단하지 않는다. 현재 제품 경로는 trusted keyup/mouseup과 CDP target별 응답을 확인하고, target 소실에서는 실패 trace/warnings와 `cleanup.partial`을 유지한다. 세대가 바뀌기 전에 전송된 명령은 `inFlight`/`inFlightEffectsUncertain`으로 구분한다. 구 세대의 전송 전 검사와 응답 후 검사를 통과해야 후속 호출을 계속할 수 있으며, 새로운 호출은 최근 reset 장벽 뒤에서 시작한다. 미재현 동시성 가설이나 다음 slice의 계약을 이번 확정 버그로 올리지 않았다.

### 계약·증거·비교 근거 감사

- 브라우저 엔진의 scope는 각 호출에 고정된 세션/세대 provenance를 붙이고 CDP·직접 탭/다운로드·file broker 호출에 전송 전후 검사를 적용한다. mutable 전역 current scope에 의존하지 않는다. background와 offscreen의 worker identity/requestId 검사도 새 Worker에 구 결과가 전달되는 경로를 막는다.
- `SessionLifecycle.reset`은 세대/epoch를 갱신하고 기존 operations를 취소한 뒤 정리 장벽을 연결한다. 기다리는 이벤트와 그 이벤트를 발생시키는 입력을 하나의 직렬 큐로 잠그지 않는다. 명시 reset은 접수 시 이미 세대가 증가하므로 bridge가 runtimeReset 결과를 다시 증가시키지 않으며, 실제 자동 VM 재생성만 한 번 증가시킨다.
- pending-job pump의 실제 host stack 예외는 현재 실행 실패에 연결한다. 사용자가 만든 guest 예외 이름/문구만으로 VM을 파괴하지 않는 기존 경계는 제품 회귀에서 유지된다.
- fixture는 실제 key/mouse 이벤트, input 값, 늦은 버튼 클릭 횟수를 수동 기록한다. 제품 테스트가 판정 API/내부 상태를 직접 변경하거나 page.evaluate로 PASS를 주입하는 경로를 발견하지 못했다. target 소실 테스트에서 독립 관찰자가 닫은 탭은 자기 임시 탭이며 reset/release 자체는 제품이 수행한다.
- native oracle의 기존 rAF/DOM relay 실패는 원시 로그에 보존된다. 최종 child locator focus/press와 부모 DOM polling은 trusted keyup이라는 판정 조건을 유지한다. 새 native oracle의 준비 방법 변경을 제품 입력 대체로 해석하지 않았으며, 특정 과거 실패의 원인이 확정됐다는 주장도 없다. 이번 전체 실행에서도 native fixture가 통과했다.
- manifest의27개 전달 파일 SHA와 존재하는 원시27개 sourceSha가 모두 일치한다. `after-product.json`에 기록된 소스 전부가 현재 head와 같다. 당시 git metadata는343a6e1/dirty=true이지만 실제 파일 SHA로 캡처 소스가 특정되며, 이번 all/headed/probes는 정확3d4246f/dirty=false다.
- Before와 After의 소스 차이는 정확 `bridge/server.mjs`, `extension/runtime-worker.mjs`, `extension/offscreen.js`, `extension/browser-engine.mjs`, `extension/files.mjs`, `extension/background.js` 여섯 파일이고, Before의 여섯 hash는 정확05b0e6a의 파일과 같다. 최종 fixture/tests/helper/안내/의존성과 미사용 새 lifecycle 모듈은 고정한 통제 비교다. 전체 과거 환경 재현 주장은 없다.
- Before1 PASS/6 FAIL→After7 PASS 집계를 원시 결과/로그와 대조했다. 첫 Before 실패는 새 metadata 검사에서 발생했으며 변수 제거·A/ref·다른 세션·asset/완료 파일 보존 자체는 이전에도 됐다는 보고가 유지된다.
- Codex 자료는 own fixture의 변수 reset/같은 tab·A 유지에 한정된 LIVE 수신 출력 전사다. 원본 tool payload 자동 export나 actual release/late hostcall 실측으로 표시하지 않는다. Aside는 CLI1.26.1028.2335/Skill3의 public guide/help DOC이며 explicit reset 방법 미확인은 API 미지원 판정으로 쓰지 않는다. 문서·실측·미측정 등급과 측정 한계가 일치하며 크기/성능 우위를 주장하지 않는다.
- B01C의 추가 리뷰/증거와 완료 상태 반영은 이전 PR14의 정확41ff8e3 리뷰와05b0e6a 머지 이력으로 구분되어 있다. B01D의 조건 ledger는 국소 제품 PASS이고 slice 자체는 리뷰/머지 전 in-progress다. 전체185 REQ 완료로 확대하지 않는다. 외부3개/내부64개와 개인용 로컬 전송 범위도 유지된다.

## 미검증·차단

- 필수 명령의 환경 차단 없음. 외부 Naver1건은 SKIP이며 외부/회사 사이트 전체는 미검증이다.
- 이 리뷰에서 Before 사본을 새로 기동하지 않았다. 원시 결과·기준 소스 hash·최종 고정 입력/소스 차이·집계를 확인하고 현재 After는 직접 재실행했다.
- 경쟁 Codex/Aside LIVE를 새로 실행하지 않았다. 저장 전사/guide 캡처의 범위와 hash만 확인했다. 전사에서 당시 원본 tool payload를 복구하거나 미측정 입력 해제를 추론하지 않았다.
- 진행 중 down의 의도적 adapter 지연/timeout/재시도는 단위 증거다. 실제 Chrome의 전송중 host 조회 불확실성은 추가로 검증했지만 임의 CDP 연결 고장·모든 드래그/chooser 실패 순서를 실환경에서 만들지는 않았다.
- 장기/최대 동시 세션 부하, 프로세스 peak 메모리·강제 crash/서비스워커 중단·브리지 재연결의 모든 조합은 미검증이다. 후속 B01E 및 B02~B06 전체 계약은 이번 판정 밖이다.

## 잔여 위험

이미 전송된 브라우저 명령과 페이지 자체의 비동기 효과는 취소/rollback을 보장할 수 없다. 현재 결과는 이를 불확실성과 partial 경고로 구분하며, target 소실 후의 release 기록은 다음 reset에서도 반복 경고가 날 수 있다. complete는 실제 adapter의 성공 응답을 확인했다는 의미이고 브라우저 전체 상태의 원자적 복원을 뜻하지 않는다.

유한한 회귀·추가 반례가 모든 타이밍 경합을 포괄하지 않는다. 과거 native relay 간헐 실패나 다운로드 취소 간헐 timeout의 원인은 이번 통과만으로 해결됐다고 판단하지 않는다. 이번 범위에서 재현되지 않은 가설은 확정 버그 목록에 넣지 않았다.

자기 테스트 브라우저/확장/fixture/bridge는 helper의 finally/close로 종료했다. 제품/테스트/문서 원본과 HEAD는 유지됐으며 원격 승인/머지를 수행한 것은 아니다.
