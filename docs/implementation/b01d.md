# B01D: 초기화 세대·호출 취소·실제 입력 해제

초기화가 이전 Worker의 응답만 버리던 경로를 보완했다. background의 각 hostcall에 고정된 세션/세대 provenance를 연결하고, 초기화 장벽 뒤에서 새 호출을 시작한다. 이전 호출은 CDP·탭·다운로드·파일 전송을 이어 보낼 수 없다. 이벤트 대기와 이를 발생시키는 입력은 동시에 실행한다. 키/마우스와 interception은 실제 해제를 시도하고 성공·실패·전송 중 불확실성을 반환한다. 개인용 로컬 중계기이며 계정 서비스를 추가하지 않는다. 독립 리뷰 전으로 slice는 in-progress다.

## 구현 경계

- SessionLifecycle는 세대와 정리 장벽·operation cancellation·in-flight metadata만 담당한다. 브라우저 동작을 Node에서 실행하지 않으며 다중 사용자 권한/할당량을 만들지 않는다.
- offscreen은 worker identity와 active request를 확인하고, 실제 VM 재생성의 자원 오류/worker 오류/watchdog/명시 reset을 공통 background 정리에 연결한다. 호스트 결과가 새 Worker로 전달되지 않는다.
- browser-engine은 공유 탭/문서 상태를 유지하면서 각 호출에 독립 scope를 붙인다. mutable global current scope를 사용하지 않는다. 직접 Chrome API와 파일 broker도 전송 전후에 검사한다. 구 세대 catch/finally가 새 포인터/프레임 상태를 덮지 않도록 중단한다.
- 실제 down/interception dispatch를 기록하고 해제 응답을 확인한 항목만 삭제한다. 실패는 유지되어 다음 reset에서 재시도할 수 있다. 이미 사라진 target은 반복 정리에서도 경고가 남을 수 있다.
- worker pending-job pump의 실제 호스트 예외를 현재 실행의 실패 경로에 연결했다. 동기 eval에서만 잡히던 stack 오류가 await 뒤에서 watchdog으로 오인되지 않는다. 일반 guest 예외 이름/문구를 VM 파괴 근거로 삼지 않는 B01C 정책은 유지한다.

## 구현 중 발견한 회귀와 fixture 관찰 보완

초기 통합에서 명시 reset 결과의 runtimeReset:true가 중계기의 기존 자동 증가와 겹쳐 세대가 두 번 증가했다. request의 operation으로 명시 reset/JS 실행 제한을 구분해 정확 한 번만 증가하도록 보완하고 별도 전송 단위로 고정했다. await 이후 실제 stack 예외가 pending-job pump 밖으로 나가던 경우도 현재 실행 실패에 연결했다.

추가 어댑터 probe에서는 debugger 연결을 거절한 뒤 새 owner 예약이 남아 다른 세션의 연결을 막는 회귀가 확인됐다. 거절/미전송일 때 새 예약을 되돌리되 실제 연결/전송 중 연결이나 기존 소유권은 보존한다. 동일 어댑터 반례에서 이전 TAB_OWNED_BY_ANOTHER_SESSION이 실제 연결 성공으로 바뀌었고 단위 회귀에 추가했다. 이 어댑터 단위는 실제 Chrome 제품 PASS와 구분한다.

native oracle의 전역 keyboard를 교차 프로세스 click 직후 보내는 경로에서 부모 relay의 keyup 관찰이 간헐적으로 빠졌다. 첫 rAF 대기 실패와 후속 DOM polling 실패를 원시 로그에 보존한다. 별도 native probe는 child에 실제 keyup이 있고 parent 전달이 늦는 사례를 기록했지만 동일 실패 run의 확정 원인으로 단정하지 않는다. 최종 oracle은 child locator의 명시 focus/press 경로와 실제 DOM polling을 사용하며 같은 trusted keyup 조건을 유지했다. 해당 oracle3회와 후속 전체 회귀에서 판정한다. fixture verdict를 조작하거나 제품 테스트를 native 입력으로 대신하지 않았다.
