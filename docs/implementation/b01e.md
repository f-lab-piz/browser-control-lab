# B01E: 페이지 함수의 비동기 실행과 JSON 경계

Scope/Locator의 evaluate, evaluateAll, waitForFunction에 같은 함수 전달·직렬화 경로를 적용했다. 함수는 선택한 문서에서 한 번 실행하고 Promise/thenable이 끝난 뒤 결과를 검사한다. QuickJS 변수나 내부 wrapper의 지역변수는 페이지 함수로 전달하지 않는다. 개인용 로컬 중계기와 외부3개·내부64개 API 구성은 유지한다. 아직 독립 리뷰 전이며 slice는 in-progress다.

## 구현과 호환 변경

- shared/json-value는 양쪽 runtime에 같은 함수 소스를 설치한다. 손실되는 객체 변환 대신 JSON 텍스트를 전달하고 JSON.parse로 복원하여 -0과 __proto__ 데이터를 보존한다. toJSON/getter를 실행하지 않고 own enumerable data/dense array만 허용한다.
- Acorn으로 정규/화살표/메서드 source를 구문 분석한다. computed property 이름을 실행하지 않고 메서드 몸체를 옮긴다. 페이지 함수는 wrapper 밖에서 별도 handle로 컴파일한다. native/bound/비전달 함수는 명시 오류다. 경쟁 제품 코드·번들·WASM은 사용하지 않았다.
- CDP의 low-level undefined/NaN 변환 전에 결과를 검사한다. 사용자 throw의 이름/문구로 내부 오류 단계를 추정하지 않고 실행 단계와 직렬화 단계를 나눈다. 단일 evaluate의 자동 재실행은 없다.
- waitForFunction의 deadline은 JS 호출 시 stamp부터 연결 준비와 Promise settle까지 포함한다. 시간이 끝나면 기존 lifecycle scope도 후속 dispatch를 막고 context 감시·private remote handle을 정리한다. release는 원래 target의 해당 handle만 대상으로 하며 문서 함수/입력을 실행하지 않는다. 이미 전송된 Promise 자체의 강제 종료는 보장하지 않는다.
- 기존 회귀의 준비 함수 중 console/append만 하던 것은 return null로, DOMnode를 readiness predicate로 반환하던 것은 Boolean(동일 요소)로 명시했다. 업무 판정 조건은 유지한다. 기존 첫 전체 실행의 review-boundary7개는 공통 준비에서 DOMnode 반환이 거절되어 실패했고 원시 로그를 보존한다.

## 독립 리뷰1차 지적 반영
