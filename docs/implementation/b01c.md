# B01C: 출력·이미지·실행·전송 예산

요청별 공통 출력 버퍼를 추가해 텍스트·이미지·블록을 분리 계산한다. console의 NUL/Unicode와 순환 표지를 보존하고, PNG는 파일 구조·CRC·scanline·zlib checksum을 검사한 뒤 완전한 이미지로만 전달한다. 메모리/스택 자원 실패는 RESOURCE_LIMIT와 새 generation으로 구분한다. 독립 리뷰 전이며 slice는 in-progress다.

## PNG·자원 구현과 검증 등급

PNG fixture는1×1 RGBA 픽셀과 정확한 파일 길이의 ancillary tEXt chunk로 구성한다. 독립 Chromium의 createImageBitmap/canvas oracle에서128 bytes·4MiB±1/정확 경계의 실제 픽셀[12,34,56,255]를 확인했다. 이 oracle은 제품 PASS와 구분한다.

범용 fast-png8.0.0의 실제 decode/checkCrc와 fflate0.8.3의 고정 출력 버퍼를 사용한다. 구조·inflated scanline 길이·Adler checksum을 따로 확인해 작은 IHDR 뒤에 과도한 압축 출력을 넣는 경우를 거절한다. PNG raster/scanline 작업 공간은64MiB로 제한하고 IMAGE_RESOURCE_LIMIT를 명시한다. 파일 한도 이내라도 이 환경의 VM/decoder 제한을 숨기지 않는다. 원본 경쟁 제품 코드/WASM은 사용하지 않았다.

QuickJS guest 오류의 name과 실제 호스트 WebAssembly RangeError를 구분한다. 물리 스택 RangeError는 VM 재사용을 시도하지 않고 종료한다. 자원 실패 결과가 runtimeReset:true일 때 기존 offscreen 수명 경로가 VM을 제거하고 중계기가 generation을 갱신한다. B01D의 전체 late hostcall·입력 release 충족을 대신하지 않는다.

## Codex·Aside·우리 도구의 실제 비교

동일 값과 자기 참조 객체의 bounded console 코드를 실행했다. 경쟁 도구는 UI/사용자 데이터를 읽지 않았고, Codex의 임시 빈 탭은 닫았다. 우리 도구는 같은 코드의 Before/After를 실제 확장 경로로 실행했다. 변수 이름만 표면별로 다르다.

|항목|Codex CUA js LIVE|Aside CLI1.26.1028.2335 one-shot REPL LIVE|우리 Before→After LIVE|
|---|---|---|---|
|NUL·Unicode·객체|NUL과 한😀 보존, inspect 형태 객체|NUL 뒤 y 누락, 한😀/객체는 표시|NUL 뒤 누락→NUL/Unicode/JSON 보존|
|자기 참조|[Circular *1], 이후 after 출력|RangeError 출력 후 after 도달 안 함(CLI exit0)|[object Object]→[Circular], after 출력|
|마지막 표현식|42 자동 출력 없음|선행 오류로42 판정 불가|Before/After 모두 자동 출력 없음|
|64KiB/이미지/16MiB|신규 실측 없음|신규 실측 없음|해당 제품·전송 경계에서 위 조건대로 확인|

[Codex 수신 출력 전사](../evidence/b01c/compare-codex-live.json)는 원본 tool payload 자동 export가 아님을 표시했다. [Aside CLI 캡처](../evidence/b01c/compare-aside-live.json)는 stdout/exit을 기록한다. [우리 Before](../evidence/b01c/compare-before.json)·[After](../evidence/b01c/compare-after.json)는 코드·실행 위치·소스 hash를 포함한다. 이 bounded 실행 결과는 경쟁 전체 지원/미지원·일반 성능의 판정이 아니다. 출력 계약이 다른데 글자 수 우위를 계산하지 않는다. 나머지 DOC/HISTORICAL 근거는 [기존 참고 방식](../requirements/reference-methods/runtime-output.md)을 유지한다.
