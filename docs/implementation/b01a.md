# B01A: 개인용 중계기의 요청 식별·접수 검증·안내

중계기는 한 사람이 로컬에서 쓰는 연결·전송 프로그램으로 유지한다. 대화별 세션은 JS 상태와 작업 소유를 구분하고 하나의 클라이언트 토큰은 본인의 세션을 관리한다. 사용자 계정·다중 사용자 인증 서비스를 추가하지 않았다. 제품 JS와 브라우저 동작은 확장 QuickJS 경로로 실행한다.

## 변경과 Before/After

|조건|Before|After|
|---|---|---|
|동일 ID의 다른 code/실효 timeout/operation|202로 이전 요청을 조용히 재사용|409/REQUEST_ID_CONFLICT, 새 실행·reset 부작용0|
|정상 재전송|기존 기록 재사용|유지. 생략 timeout과 명시30000은 같은 실효 요청|
|reset 후 기록/연결 끊긴 뒤 동일 재조회|offline JS는 조회 전에503|기존 tombstone 재조회 허용·신규 JS는503, 세대와 효과 중복 없음|
|문자열/소수 timeout·객체 requestId|202로 접수|접수400·요청/세대 무변경|
|HTTP 조각 사이 한글|한이 대체문자로 손상됨|UTF-8 bytes를 모아 한 번 디코딩·잘못된 UTF-8 거절|
|guide|버전·검증 범위 없음, unknown은200/api:null|version·기본 검증 범위 안내, 외부/내부 정확한 이름 조회, unknown은404/UNKNOWN_API|

새 전송 단위5개는 Before0 PASS/5 FAIL→After5 PASS다. 동일 제품 시나리오4개는 Before2 PASS/2 FAIL→After4 PASS이며 창을 띄운 Chrome에서도 확인했다. Before/After의 최종 테스트·fixture·기타 기록 source hash는 같고 bridge/server.mjs만 다르다. 단위의 extension poll 시뮬레이션은 제품 실행으로 집계하지 않는다.

이 표는 경쟁 내부 구현·전체 동등성·성능 우위의 증명이 아니다. 경쟁 도구의 HTTP 요청 식별 계약은 공개 API로 직접 대응하지 않아 이번 PR에서 수치를 만들지 않았다. 참고 자료의 DOC/HISTORICAL/LIVE 상태를 바꾸지 않는다. 근거는 [guide](../requirements/reference-methods/runtime-output.md#ref-guide), [js](../requirements/reference-methods/runtime-output.md#ref-js), [공통 runtime](../requirements/reference-methods/runtime-output.md#ref-runtime)과 연결된 source/claim 레지스트리(조사일2026-11-01)다. 이번 경쟁 브라우저 신규 run0.

## 검증과 재현

- `npm test`:12/12 PASS(기존7+새 전송5).
- `npm run test:all`:55 PASS/외부1 SKIP/FAIL0. fixture7·bootstrap1·기존 제품24·요구 제품4·경계7을 포함하며 unit12와 별도로 집계한다. 기존 메일137·회의실 예약·가상 메뉴230·파일 업무도 통과했다.
- `HEADED=1 npm run test:requirements`:4/4 PASS, Chrome for Testing145.0.7632.6, 별도 임시 프로필. 마지막 세션 binding 분리 assertion도 이 실행에 포함했다.
- `python3 docs/requirements/tools/validate.py`, `validate_development_plan.py`, `test_validate.py`, `test_development_plan.py`: 문서/계획 구조 검증. 제품 PASS를 대신하지 않는다.
- Before는 base3c87245의 bridge/server.mjs를 사용하고 같은 최종 테스트/fixture를 실행했다. 임시 교체는 finally로 원복한 뒤 After를 실행했다. 재현 시 별도 checkout에 최종 테스트를 적용하고 해당 제품 파일을 base로 두면 된다.

원본/전달 파일 SHA와 phase·명령·집계는 [manifest](../evidence/b01a/manifest.json)에 있다. 로그의 실제 저장소 경로만 <repo>로 정규화했고 원본 hash도 남겼다. 별도 browser/server는 테스트 종료 때 정리한다.

## 제한과 후속

외부 서비스 테스트1건은 기본 설정에 따른 SKIP이며 현재 외부/회사 사이트 성공을 주장하지 않는다. 이번6개 부모 요구/9조건만 pass로 기록하며185개 전체를 통과했다고 하지 않는다. lexical(B01B), 이미지 예산(B01C), late hostcall/실제 입력 release(B01D), 평가 직렬화(B01E)는 다음 작업이다. 기존 프로세스가 종료되면 요청·세션 기록을 복구하지 않는다. 독립 리뷰와 머지 완료 여부는 PR과 실행 로그에서 별도 확인한다.
