# 사용자 요구사항과 개발 계약

## 제품
독립 Chrome 확장 안에 JS 실행 환경을 둔다. 에이전트에 노출하는 도구는 guide/reset/js 세 개, JS 내부 API는64개를 기준으로 한다. 기본 기능을 조합하고 사이트별 편의 API나 업로드 경로마다 별도 툴을 늘리지 않는다. 범용 라이브러리는 허용하되 Codex/Aside 제품 코드·WASM을 복사하지 않는다.

## 관찰·검색·입력
스냅샷은 보이는 화면만이 아니라 현재 연결된 전체 DOM을 관찰한다. 화면 밖 요소를 찾아도 관찰 때문에 스크롤하지 않는다. 지연 로딩·가상화에서 DOM에 없는 데이터는 표시하지 않는다. 영역·프레임·스크롤 컨테이너·생략과 후속 조회 단서가 있어야 한다. 의미 있는 역할·접근 이름·선택/체크/확장/활성/가림 상태를 보존하고 긴 URL·스크립트·중복 leaf 텍스트는 줄인다. 속성 원문은 필요할 때 조사한다.

검색은 키워드를 이미 아는 경우와 모르는 경우를 구분한다. 먼저 상위 영역/프레임 구조를 보고 범위를 좁힌 뒤 역할·이름/필터/ref로 찾는다. 낡은 ref, 중복 매칭, 가려진 대상, readonly/disabled, iframe detach는 임의의 대상에 입력하거나 성공으로 보고하지 않는다. 클릭·드래그는 실제 브라우저 입력 경로를 사용하며 CSS transform/내부 스크롤·OOPIF 좌표를 검증한다. 스크린샷은 viewport와 전체 페이지를 기본 지원한다.

## 파일·런타임
로컬 PC 경로와 서버/Pod에서 생성한 파일을 같은 업로드 API로 전달한다. 서버 파일은 바이트 또는 staged fileId로 받는다. 다중 파일·선택창·drop·다운로드의 GET/POST/cookie/blob·실패/취소와 실제 바이트를 검증한다. 텍스트 출력과 바이너리를 구분한다. REPL 변수 유지·비동기·세션 격리·reset·시간/메모리/출력 제한·오류 복구를 명시한다.

## 테스트 사이트
기본 API별 기능과 실패 경계, 복잡 업무, 실제 외부 사이트를 분리한다. 중첩/교차 출처 iframe 내부 메일 스크롤·137번 읽기, 회의실 격자 드래그·더블클릭·폼, 가상화 긴 선택 목록·큰 DOM·긴 URL, Shadow DOM·동적 교체가 필수다. 진단 실험실은 상태 관찰·중복·지연·readonly·가림·HTML DnD·slot·파일 경로·변형 iframe을 추가한다. 단순 버튼 클릭만으로 충분하다고 보지 않는다.

사이트는 업무 완료 조건을 자체 판정하고 run별 이벤트·PASS/FAIL/대기를 표시한다. 서버 판정 API를 에이전트가 직접 호출해 PASS를 만들지 않는다. 사이트 판정은 보안 증명이 아니므로 하니스의 독립 바이트/DOM 검증도 병행한다.

## 실제 확장 자동화
별도 Chrome 프로필에 개발 확장을 자동 설치하고 HTTP 중계기로 호출한다. Playwright는 브라우저 기동·독립 판독·fixture oracle만 담당하며 제품의 실패한 입력을 대신하지 않는다. Codex/Aside 비교에서도 fixture 데이터만 사용한다. 실제 회사 사이트는 별도 접근 검증 전까지 미검증으로 남긴다.

## 이번 평가의 변경 경계
스킬·개발 문서·test-site·tests·평가 scripts만 변경한다. 툴 코드는 수정하지 않는다. 기능 부족·조용히 무시되는 옵션·거짓 성공·관찰 누락을 재현하고 개선안을 제시한다. 기존64 API의 기본 통과 기록은 전체 옵션 검증과 구분한다.
