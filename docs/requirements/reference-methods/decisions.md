# 메인 초기 상세화·참고 방식 판단

시작8503267. 조사A/B는 source와 조건·반례를 제출했고 정본은 메인만 갱신했다. 아래 판단은 제품 구현 적합성이나 경쟁 지원의 승인과 다르다.

- 상세화 수용: 기존184개 요구에252개 구체 검증 사례를 작성했다. 단순 호출/GWT 목적 반복을 실제 준비·행동·관측값/오류·부작용으로 바꿨다. case ID는 정본의REQ-Cnn이며 새 도구 수를 늘리지 않는다.
- 우리 정책 유지: 확장 QuickJS/세션·requestId·server asset·예산·ref 안정성·단일조회 strict·상태 확인은 사용자 업무/실패 반례에서 도출한 목표다. 공개 경쟁 문서가 없다는 이유로 없애거나 지원으로 채우지 않는다.
- 의도된 차이: Codex CUA의read-only 평가와 우리 효과 허용 평가, 일부 first-matched 조회와 우리strict, Aside의snapshot마다ref무효화와 우리동일문서안정ref를 구분한다.
- 조정 채택: 공개된 선택·프레임/부분조회·대기/파일선택창·다운로드 완료/경로 확인 흐름은 참고한다. 파일/이벤트 관련 API를 늘리기보다 공통 엔진·옵션·기존 호출 조합으로 구현한다.
- 보류: Aside guide의listBrowserTabs와help의getTabs 차이, public 계약이 없는 세부API, 실제bytes/오류/경합 정책은 미확인/차단으로 남긴다. 모르는API예제를 만들어 채우지 않는다.
- 관찰 경계: Codex blank run은빈DOM count/조회만, 이전audit은당시일부호출만 증거다. 새서버fixture가존재해도 실측하지않은결과는예제/검증설계다. 다른adapter 관측은IAB동등확인으로합산하지않는다.
