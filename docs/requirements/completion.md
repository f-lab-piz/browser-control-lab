# 개발 전 요구사항 정립 결과

2026-11-01. 제품 기준은 main 700a6a06af3f97729327afaf9becb4ee29bb475b. 제품 구현·테스트·fixture·빌드 파일은 기준과 동일하다.

외부3개·내부64개 API 명세와 공통5개 계약, 근거 레지스트리·검증계획·요구별 개발매핑을 정리했다. Sol6.1 high의 독립 새 컨텍스트 검토를 세 번 순차 수행하고 각 제안의 메인 판단을 기록했다. 각 회차 보고서 판정은 당시 초안에 대한 명세 검토이며 최종 제품 승인/PASS가 아니다.

이번 결과에서 확정한 것:

- 검색 본문/접근이름/원문을 구분하고 인접span·실제공백·긴문자열·ARIA/hidden·조합순서 정책을 명시했다.
- 키워드 없는 프레임/영역/내부scrollport 발견, 출력예산·생략·continuation/문서세대·diff 정합성을 명시했다.
- 상태/좌표/입력 사후확인, 명시down과press의 modifier 소유를 구분했다.
- 로컬/서버/inline 파일 schema·바이트 검증, 실제 다운로드·저장 반복/동명 충돌·최종 취소상태·event identity/ordering을 명시했다.
- runtime reset/late결과/비멱등 재전송·텍스트/이미지출력·로그 유실관찰 계약을 명시했다.

이 결과는 목표 계약이다. 신규 규범별 제품 충족은 미검증으로 남겼으며 기존 PASS를 새 요구의 PASS로 바꾸지 않았다. 비교는 Aside 안내 캡처·기존 Codex/Aside 동일fixture 실측·설계 판단을 구분했고 새 경쟁 제품 벤치마크나 회사사이트 실행은 하지 않았다.

다음 개발은 backlog의 B01~B06에서 요구별 실패 재현·fixture/assertion 추가부터 시작한다. 이번에는 제품/테스트를 수정하거나 개발 PR을 올리지 않았다.

최종 집계: **API 명세67개 + 공통5개, 요구184개(MUST181/SHOULD3), 독립 검토3회, 제안17건 전부 판단·수용, 개발 작업6묶음**. 리뷰에서 남긴 필수 충돌/미정 기대값은 메인이 정리했다. 구현·검증 상태는 전184개 미검증이며 담당 작업/PLAN ID는 모두 연결했다.
