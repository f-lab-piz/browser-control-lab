## Confirmed findings

### P2 — Bind CSS `:scope` to the selected document rather than every candidate

- Exact location: `extension/page-agent.mjs:51`.
- Condition: a normal HTTP HTML document contains `<body id="body">`; invoke `page.locator(':scope > body').count()` or `.getAttribute('id')` through HTTP → extension → QuickJS.
- Expected: selected document CSS scope has one body and reads `body`. Native read-only `document.querySelectorAll(':scope > body')` returns 1. `document.querySelectorAll(':scope')` returns only HTML.
- Actual: count is 0 and single read fails `ELEMENT_NOT_FOUND`. `locator(':scope')` returns every enumerated physical/open-shadow element (10 in the independent fixture).
- Cause: `all(...).filter(el => el.matches(query.value))` binds the CSS `:scope` pseudo-class to each candidate element. This is unrelated to Chrome navigation/observer failures.
- Impact: valid scope-relative CSS cannot select targets in the current document, and root discovery can incorrectly produce multi-match errors. It violates the document CSS meaning of REQ-SCOPE-LOCATOR-001/C01; no CSS `:scope` exclusion was found in the accepted contract.
- Origin: existing base defect, not introduced as a new bug by this PR. The exact-base owning files (`api-source.mjs`, `page-agent.mjs`) reproduced 0 / ELEMENT_NOT_FOUND and `:scope` matching all 6 base-enumerated candidates. The current CSS enumeration expands those candidates to 10; that is not represented as a new root cause.
- Reproduction: `BCL_RUN_DIR=output/pr20-rereview/probe node output/pr20-rereview/probe.mjs`. Current evidence: `output/pr20-rereview/independent-probes.json`. Base evidence: `output/pr20-rereview/baseline-independent-probes.json`. The base control is an archive of the reviewed head with only those two files restored using exact `git show 0452cbe...`; dependencies/fixture/harness are fixed and the control was executed from its own cwd. Its two SHA256 values match exact git-show bytes. This is not a complete historical environment replay.

No confirmed P0/P1/P3 findings. The first review's inactive composed-descendant and html/head issues are fixed and covered by the current 12 B02A product tests. The new `:scope` finding is separate from those fixes.
