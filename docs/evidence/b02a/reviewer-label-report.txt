## Findings

### [P2] Reject absent explicit labels before matching empty-capable regular expressions

- Location: `extension/page-agent.mjs:59` (with `name(...,{explicitOnly:true})` returning `''` at line38).
- Requirement: `docs/requirements/common/selection.md:153` limits getByLabel to controls connected to an explicit ARIA/native label source; `REQ-SCOPE-GETBYLABEL-002-C02` requires an absent label to produce zero matches and reject mutation.
- Reproduction: serve `label-fixture.html`, which contains one `<input id="unlabelled" placeholder="Only Hint" value="initial">` and no label/ARIA naming source. Through HTTP → extension → QuickJS, call `p.getByLabel(/^$/).evaluateAll(els=>els.map(el=>el.id))`, then `p.getByLabel(/^$/).fill('changed-without-label')`.
- Expected: no identity, count0, rejected fill, value `initial`, zero input events.
- Actual at reviewed head: identity `["unlabelled"]`, count1, accepted fill, value `changed-without-label`, one independently observed trusted input event. The ordinary literal placeholder query returns0, so existing string-only negative coverage misses this boundary.
- Cause: the absence of an explicit label is encoded as an empty string and tested as though it were an actual label. A RegExp matching the empty string therefore creates a label connection that does not exist. Strict selection does not protect the single-candidate case.
- Impact: an absent label can resolve to an unrelated editable control and cause real input instead of the required safe failure.
- Introduced/worsened in this PR: the same fixture/probe/harness/dependencies with only api-source/page-agent restored to exact base selects no control for `/^$/`, rejects fill (`ELEMENT_NOT_FOUND_TIMEOUT`), and preserves `initial` with zero events. Both restored owner-file hashes match `git show 0452cbe...`. This is a controlled two-file comparison, not a full historical environment replay. The enclosing Git metadata in the baseline JSON still says current HEAD; source hashes, baseline cwd and `label-baseline-audit.json` establish provenance.
- Evidence: `label-probe.json`, `label-base.json`, `label-head.log`, `label-base.log`, `label-base-runtime.json`, `label-baseline-audit.json`, `label-native.json`.
- Recommended correction: distinguish absent explicit label provenance from a valid name before regex matching; add public product negative coverage that verifies both zero selection and no actual input. The scope remains B02A.

No other confirmed P0/P1/P2/P3 findings were identified in the reviewed scope.
