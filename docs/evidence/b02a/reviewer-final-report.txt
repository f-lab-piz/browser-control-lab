# PR20 B02A 독립 라벨 재리뷰

## 발견 사항

범위 내 P0/P1/P2 제품 결함은 발견하지 않았다. 이전 보고서의 결론을 승인 근거로 삼지 않고 지정 base→head diff, 연결 구현·테스트·fixture·가이드·정본·ledger·증거를 읽고 새 실행으로 확인했다.

### P3 · 추가 증거 텍스트의 마지막 빈 줄이 diff 검사를 실패시킴

- 위치: `docs/evidence/b02a/label-aside-guide.txt:88`, `docs/evidence/b02a/label-aside-repl-guide.txt:153`.
- 재현: `git diff --check 0452cbe2474ed73069167c43d683ae1514c4f29c 23aff96a23710c41702eb0079cd99b7e221144f4`.
- 기대: 추가한 증거 파일에 Git whitespace 위반이 없고 exit 0.
- 실제: 두 파일의 `new blank line at EOF`로 exit 2. 원시 결과는 `diff-check.log`에 보존했다.
- 영향: 제품 선택·입력에는 영향 없는 증거 형식 정리 항목이다. PR에서 추가한 파일에 도입됐다. 정상적인 diff 검사 통과를 위해 마지막 빈 줄을 정리하고 manifest의 보존 파일 해시도 함께 갱신하면 된다. 리뷰어는 tracked 파일을 수정하지 않았다.
- 처리: 비차단 P3. 메인에게 전달했고 메인이 최종 문서 정리 커밋에서 처리할 계획이라고 회신했다. 현재 검토 SHA에서는 미수정 상태이며 diff 검사가 통과했다고 표현하지 않는다.

## 독립 경계 probe

`probe.mjs`가 ignored 경로에서 직접 별도 HTTP fixture를 제공했다. 제품 조작은 bridge client.js→HTTP→확장→QuickJS로만 수행했다. Playwright는 기동과 독립 DOM/이벤트 판독에만 사용했다. 사이트 판정이나 업무 이벤트를 외부에서 주입하지 않았다.

1. 빈 native label, 빈 유효 IDREF 및 inert 본문만 가진 유효 IDREF는 빈 이름으로 선택됐다. 무라벨·빈 aria-label만·깨진 IDREF만 있는 입력은 `/.*/g` 후보에 포함되지 않았다. `gy` 정규식 상태가 빈 후보들을 건너뛰지 않았다. 빈 상위 IDREF에서 비어 있지 않은 aria-label로 fallback, 숨긴 native label의 직접 참조, ShadowRoot 지역 이름과 바깥 같은 ID 분리, 문서 `:scope` 및 inert 본문 제외도 확인했다.
2. 빈 이름 3개를 대상으로 fill하면 MULTIPLE_MATCHES였다. placeholder-only/없는 label의 fill은 대상 없음으로 거절됐다. 실제 무라벨 값은 initial, 이벤트는 빈 배열로 유지됐다.
3. 유효한 fallback label의 fill과 role 버튼 click은 정확한 대상에서 각각 1회의 실제 trusted input/click을 발생시켰다. 결과는 `probe.json`에 보존했다. 이 3그룹은 정식132/45에 추가하지 않았다.

## 정본·diff·증거 확인

- AGENTS.md, 프로젝트 SKILL, pr-review/autonomous-implementation 지침과 관련 architecture/testing 및 selection/locator/role/label/text 정본을 적용했다.
- B02A의 13부모/21조건 ledger가 정본 조건과 일치하고 모두 제품 테스트에 연결돼 있다. 현재 slice는 독립 리뷰/머지 전 in-progress이며, B02B 이후15개 slice는 모두 not-started다. executionScope는 through B02A / afterCompletion stop이다.
- 실제 소유 코드 변경은 api-source/page-agent 두 파일이다. 검색 인자 거절, IDREF 우선순위·root·중복·순환, full name/body와 축약 출력 분리, composed 최소 후보, CSS document/ShadowRoot native query, stale/strict/명시 wait 예외와 최종 label 부재 sentinel을 연결 경로에서 확인했다.
- getByLabel의 부재는 null, 유효한 빈 연결 이름은 빈 문자열로 구분된다. 새 공식 테스트는 무라벨 3정규식 조회0·거절 fill·값/이벤트 불변과 연결 빈label의 정상 trusted fill 및 사이트 PASS를 모두 검사한다. 조회0만으로 무입력을 추정하지 않았다.
- 기존 details 회귀는 SUMMARY/BUTTON 양쪽 identity를 새로 확인한 뒤 의도한 native button을 CSS+filter로 명시한다. strict를 느슨하게 하거나 임의 첫 요소를 선택하지 않으며 숨김 제외와 실제 clicked 결과를 유지한다.
- B02A61개와 B01E24개 manifest 보존 파일 해시가 모두 맞았다. 최종 Before/After/headed의36개 source fingerprint를 확인했다. Before는 현재 고정 입력에 소유2파일만 exact base로 복원한 통제이며 git show 해시와 일치한다. After/headed는 현재 소스와 모두 일치한다. Before3PASS/10FAIL→After13PASS와 일치한다. 저장 당시 HEAD/dirty=true는 구현 커밋 전 상태이고 소스 지문으로 검증했다. 이번 clean exact-head 실행과 혼동하지 않는다.
- Codex/Aside 비교는 동일 fixture, root 범위, 실제 측정·수신 출력 전사·원시 CLI의 구분과 제한을 명시한다. label 비교 fixture hash도 현재와 같다. 경쟁 도구의 차이나 DNS 차단을 전체 제품 미지원/우열로 과장하지 않는다. 이번 리뷰에서는 비교를 새로 실행했다고 주장하지 않는다.

## 미실행·차단과 남은 위험

- 외부 네이버 실환경과 회사 사이트는 미실행이다. 개인 프로필/계정 및 배포는 다루지 않았다.
- 경쟁 제품 비교의 신규 재실행, 전체 과거 base 환경 재생, 전체185REQ 수용 검증은 하지 않았다. 기존 Before는 명시된 두 소유 파일 통제의 증거로만 확인했다.
- B02B의 locator 조합, B03A 이후 프레임 수명·snapshot·입력/파일·wait 전체 검증은 승인 범위 밖이며 미완료 자체를 B02A 버그로 간주하지 않았다. 모든 AX 규칙·브라우저·사이트의 동등성도 주장하지 않는다.
- PR18의 과거 headed frame-tree timeout 원인은 아직 미입증이다. 이번 전체/단독 headed에서는 재현되지 않았으며 해결됐다고 판정하지 않는다.
- 스냅샷의 모든 신규 규범을 이번 검색/이름 21조건의 통과로 대신하지 않는다. P3 공백 정리 뒤 SHA가 바뀌면 이 보고서는 위 SHA에 대한 제품 검토이며 후속 변경은 별도로 대조해야 한다.
